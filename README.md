# Практична робота: Розроблення базового кросплатформного GUI-застосунку

## Тема
Розроблення базового кросплатформного GUI-застосунку «Менеджер завдань» мовою C# (.NET) з використанням кросплатформного фреймворку **Avalonia UI**.

---

## Опис застосунку
«Менеджер завдань» — це графічний кросплатформний додаток, що дозволяє:
- Додавати нові завдання (через кнопку або клавішу `Enter`);
- Переглядати список створених завдань;
- Позначати завдання як виконані за допомогою чекбоксів;
- Видаляти вибране завдання або конкретне завдання кнопкою кошика;
- Очищати всі виконані завдання однією кнопкою;
- Перевіряти коректність введення (захист від порожнього рядка);
- **Додаткове завдання:** автоматичний лічильник невиконаних завдань, що оновлюється при будь-яких діях.

---

## Структура проєкту
- `Models/TaskItem.cs` — модель завдання з підтримкою інтерфейсу `INotifyPropertyChanged`.
- `MainWindow.axaml` — декларативна розмітка інтерфейсу користувача (XAML).
- `MainWindow.axaml.cs` — логіка обробників подій взаємодії з GUI.
- `App.axaml`, `App.axaml.cs` — точка конфігурації стилів Avalonia UI (FluentTheme).
- `Program.cs` — точка входу застосунку з ініціалізацією платформи Avalonia.
- `TaskManagerApp.csproj` — конфігураційний файл проєкту .NET.

## Відповіді на контрольні запитання

### 1. Що означає кросплатформність програмного забезпечення?
Кросплатформність — це властивість ПЗ функціонувати на різних операційних системах (Windows, macOS, Linux) без необхідності переписування або суттєвої зміни вихідного коду під кожну цільову систему.

### 2. Для чого використовується Avalonia UI?
Avalonia UI — це сучасний відкритий XAML-фреймворк для C# (.NET), призначений для розробки кросплатформних графічних користувацьких інтерфейсів (GUI) з єдиною кодовою базою під десктопні, мобільні та веб-платформи.

### 3. Чим Avalonia UI відрізняється від Windows Forms?
- **Кросплатформність:** Windows Forms жорстко прив'язаний до Win32 API в ОС Windows, тоді як Avalonia працює на Windows, Linux, macOS та інших ОС.
- **Рендеринг:** Avalonia малює елементи самостійно через апаратний графічний рушій Skia, забезпечуючи однаковий вигляд на всіх платформах.
- **Технології:** Avalonia підтримує сучасну векторну розмітку XAML, стилі, Data Binding та MVVM, тоді як WinForms створюється імперативно через конструктор C#.

### 4. Як у C# обробляються події елементів графічного інтерфейсу?
Події базуються на делегатах (наприклад, `RoutedEventHandler`). В XAML подія призначається через атрибут елемента (наприклад, `Click="OnAddTaskClicked"`), а в кодовому файлі (`MainWindow.axaml.cs`) створюється метод-обробник із параметрами `(object? sender, RoutedEventArgs e)`. Також підписку можна робити програмно: `button.Click += OnAddTaskClicked;`.

### 5. Яким чином можна відокремити логіку застосунку від графічного інтерфейсу?
- За допомогою патернів проєктування, зокрема **MVVM (Model-View-ViewModel)**;
- Використанням механізму **Data Binding (зв'язування даних)**;
- Винесенням бізнес-правил та моделей даних в окремі класи/сервіси без залежностей від бібліотек інтерфейсу користувача.
